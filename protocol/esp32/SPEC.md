# ESP32 触控盒协议 v2

GameScrcpy（电脑）与 ESP32 触控盒（固件 `firmware/esp32/`）之间的协议。决定与背景见 ADR-0102；功能清单 HID-004。

- 固件与电脑共用同一个 C99 头文件 `gs_esp32_protocol.h`（常量、消息结构、编解码函数、CRC、HMAC 标签）。
- 金标准向量 `vectors.json` 由 `gen_vectors.py`（只用 Python 标准库，按本规范独立实现）生成，电脑端测试 `gs_esp32_tests` 逐字节核对。改协议的顺序：本文件 → `gen_vectors.py`（运行 `python protocol/esp32/gen_vectors.py`）→ `gs_esp32_protocol.h` → 测试。向量不手改。
- 本文所有多字节整数都是小端序。

## 1. 连接方式

| 方式 | 说明 |
|---|---|
| 串口（主） | 板子上接电脑的那个口：USB 转串口芯片（CH34x、CP210x）接到 UART0，或芯片自带的 USB 串口（USB-Serial/JTAG，C3、C6、P4；S3、S2 的原生 USB 接手机时不可用）。8N1，无流控，DTR 与 RTS 保持不动作。先以 921600 握手，再试 2000000（第 6 节）。自带 USB 串口不受波特率影响。 |
| Wi-Fi（可选） | UDP，ESP32 监听端口 4545，一个数据报装一帧再加 16 字节标签（第 7 节）。只有带 Wi-Fi 的型号（ESP32、S2、S3、C3、C6）有；P4 没有 Wi-Fi，只能用串口。 |

字节流（串口）上靠帧头重新同步；UDP 一包一帧。

## 2. 帧

```
A5 5A | 类型 u8 | 序号 u8 | 长度 u16 | 负载（0～512 字节）| CRC16 u16
```

- 帧头固定为 `A5 5A`；`长度` 是负载的字节数，超过 512 即为坏帧。
- CRC 为 CRC-16/CCITT-FALSE（多项式 0x1021，初值 0xFFFF，不反转，不异或输出），算的范围是“类型”到负载末尾（不含帧头）；`"123456789"` 的 CRC 是 0x29B1。
- 序号：发送方每发一帧加一（到 255 后回到 0），两个方向各自计数。接收方不据此丢帧，只用于日志与排查。
- 一帧最长 520 字节。

### 2.1 字节流上的同步

接收方维护一个最多 520 字节的缓冲：

1. 缓冲开头不是 `A5` 时，丢掉开头直到下一个 `A5`。
2. 开头是 `A5` 但第二字节不是 `5A`：丢掉第一个字节，并一直丢到下一个 `A5`。
3. 有了完整的 6 字节帧头后看长度：大于 512 是坏帧，同第 2 条处理。
4. 整帧到齐后核对 CRC：不对是坏帧，同第 2 条处理——也就是从坏帧第二个字节起重新找帧头，坏帧里夹着的完整帧照样能找回来。
5. 核对通过的帧交给上层，然后从缓冲里移走。

板子开机时 ROM 会在 UART0 上打印几行文字（115200），电脑照上面的规则把它们丢掉。

## 3. 消息

类型 0x01～0x3F 是电脑发给 ESP32 的，0x80～0xBF 是 ESP32 发给电脑的。负载比本表规定的长时，多出的字节忽略（以后加字段只往后加）；比本表短、或字段超出范围，就是格式错误。

文字字段一律为 `长度 u8 + UTF-8 字节`，不带结尾的 0，中间不能有 0 字节。

### 3.1 电脑 → ESP32

| 类型 | 名字 | 负载 | 说明 |
|---|---|---|---|
| 0x01 | HELLO_REQ | `版本 u8`（= 2） | 请 ESP32 回 HELLO。 |
| 0x02 | TOUCH | `触点数 u8`（0～10）+ 触点数 × `{编号 u8, 按下 u8, X u16, Y u16}` | 一帧触摸。编号 0～127；按下只能是 0 或 1；X、Y 为 0～32767，是手机自然方向（竖着拿时的左上角为原点）的逻辑坐标，旋转由电脑算好。电脑把这一帧所有按着的手指和这一帧抬起的手指（按下 = 0，带最后的位置）都写进去，ESP32 原样转成一个触摸屏报告，触点数也写进报告。 |
| 0x03 | KEYBOARD | `修饰键 u8` + `按键 6 × u8` | 标准键盘报告：修饰键位从低到高是左 Ctrl、左 Shift、左 Alt、左 Win、右 Ctrl、右 Shift、右 Alt、右 Win；按键是 HID 键盘用法码，0 为空。 |
| 0x04 | CONSUMER | `用法 u16` | 消费类按键（主页 0x0223、返回 0x0224、最近任务 0x01A2、音量加 0x00E9、音量减 0x00EA 等）；0 表示松开。 |
| 0x05 | MOUSE | `按键 u8, dx i16, dy i16, 滚轮 i8` | 相对鼠标。按键位：左、右、中、后退、前进。 |
| 0x06 | GAMEPAD | `按键 u32, 方向键 u8, lx i16, ly i16, rx i16, ry i16, lt u8, rt u8` | 通用手柄。方向键 0～7 从上开始顺时针，8 = 回中；摇杆 −32767～32767（ESP32 把 −32768 当成 −32767）；扳机 0～255。没有震动。 |
| 0x07 | RELEASE_ALL | 空 | 抬起所有手指、松开所有按键与鼠标键、手柄回中。 |
| 0x08 | PING | `令牌 u32` | ESP32 回同一令牌的 PONG。也算保活（第 5 节）。 |
| 0x09 | SET_BAUD | `波特率 u32, 令牌 u32` | 只对 UART 有效，见第 6 节。 |
| 0x0A | WIFI_SET | `SSID`（文字，1～32 字节）+ `密码`（文字，0～64 字节）+ `密钥 32 字节` | 保存到 NVS 并连接；密钥用于 UDP 标签（第 7 节）。只接受从串口来的这条消息。 |
| 0x0B | WIFI_FORGET | 空 | 删除保存的 Wi-Fi 与密钥，断开。 |
| 0x0C | SET_NAME | `名字`（文字，1～32 字节） | 板子的名字：蓝牙设备名、mDNS 实例名、HELLO 里的名字。 |
| 0x0D | REBOOT | 空 | 重启。 |
| 0x0E | ENTER_DOWNLOAD | 空 | 设“强制进下载模式”标志后重启，ROM 进入串口下载模式（用于刷写，见第 9 节）。经典 ESP32 没有这个标志，回 ERROR（不支持）。 |

WIFI_SET、WIFI_FORGET、SET_NAME 成功后 ESP32 回一个新的 HELLO（反映新的状态），失败回 ERROR。

### 3.2 ESP32 → 电脑

| 类型 | 名字 | 负载 | 说明 |
|---|---|---|---|
| 0x81 | HELLO | `协议版本 u8`（= 2）+ `固件版本`（文字，≤16）+ `芯片编号 u16` + `芯片版本 u16` + `能力位 u32` + `MAC 6 字节` + `Wi-Fi 状态 u8` + `IPv4 4 字节` + `名字`（文字，≤32）+ 可选 `扩展 u8`（= 1）+ `USB 状态 u8` + `USB 问题 u8` + `蓝牙状态 u8` + `蓝牙问题 u8` + `Wi-Fi 问题 u8` | 回 HELLO_REQ，也在设置改动后发。末尾这一段可以没有（旧固件就没有），接收方没有它时当作“不知道各部分状态”。 |
| 0x82 | STATUS | `USB 状态 u8` + `蓝牙状态 u8` + `对端名字`（文字，≤32）+ `Wi-Fi 状态 u8` + `IPv4 4 字节` | 手机那头与 Wi-Fi 有变化时主动推送（发给最近一次收到合法帧的那条连接）。 |
| 0x83 | PONG | `令牌 u32` | 回 PING 与 SET_BAUD。 |
| 0x84 | LOG | `级别 u8`（0 错误、1 警告、2 信息、3 调试）+ `文字`（≤255） | 固件的日志（ESP-IDF 的控制台在 UART0 上是关掉的，日志都走这里）。 |
| 0x85 | ERROR | `错误码 u16` + `文字`（≤255） | 1 格式错误、2 不认识的类型、3 不支持、4 存储失败、5 还没准备好。 |

- 芯片编号与 ESP-IDF 镜像头里的芯片编号相同：ESP32 = 0、S2 = 2、C3 = 5、S3 = 9、C6 = 13、P4 = 18。
- 芯片版本 = 主版本 × 100 + 次版本。
- 能力位：0x01 USB 触摸屏（原生 USB 接手机）、0x02 高速 USB、0x04 蓝牙 HID、0x08 有 Wi-Fi、0x10 这条连接是芯片自带的 USB 串口（波特率无意义）。
- USB 状态：0 本芯片不用 USB 接手机、1 没接手机或手机还没认、2 手机已认出、3 手机让 USB 挂起（例如息屏）。
- 蓝牙状态：0 本芯片不用蓝牙、1 关、2 正在广播等配对或回连、3 已连上。对端名字是手机的设备名（读不到时是蓝牙地址），没有连上时为空。
- Wi-Fi 状态：0 没有 Wi-Fi、1 没设置、2 正在连接、3 已连上（IPv4 有效）、4 连不上（密码错或找不到网络，之后仍会重试）。
- 各部分问题（HELLO 末尾那一段）：0 正常、1 这块芯片没有这一部分、2 启动失败（板子照样运行，只是这一部分用不了）、3 还在启动。USB 与蓝牙只有这一芯片用的那一个是正常的，另一个是 1。板子先回第一封 HELLO（各部分标“还在启动”），USB / 蓝牙 / Wi-Fi 起完后再回一封带结果的。

## 4. 握手

1. 电脑以 921600 打开串口（DTR、RTS 都不动作，免得把板子复位），清空输入，发 HELLO_REQ。
2. 300 毫秒内收到 HELLO：按 v2 工作；协议版本不是 2 时照样连接，但只用本规范里有的消息。
3. 300 毫秒内没有 HELLO：看板子在这段时间里发来的字节（第 8 节）。只有认出旧固件的招呼才按旧固件处理；反复出现的 ROM 启动文字、`waiting for download`、认不出的字节或什么都没有都**不**按旧固件，电脑报出具体原因并放弃这次连接。
4. UDP 没有旧固件：每 500 毫秒发一次 HELLO_REQ，3 秒没有回复就算连不上。

握手用的 HELLO_REQ 帧不含 0xF4 字节（电脑挑一个使帧里没有 0xF4 的序号），免得旧固件把它当成触摸包的开头。

## 5. 保活与安全

- ESP32 连续 2 秒没有收到电脑的任何合法帧（包括 PING），就抬起所有手指、松开所有按键与鼠标键、手柄回中，手指不会卡在手机上。
- 电脑在 500 毫秒内没有发过帧时发一个 PING，顺便用 PONG 算往返时间。
- 3 秒没有收到 ESP32 的任何帧时，电脑认为连接已断。

## 6. 波特率

1. 握手在 921600 完成。经 USB 转串口芯片（CH34x、CP210x）连接时，电脑接着发 SET_BAUD（2000000，令牌 t）。
2. ESP32 先用原来的波特率回 PONG（令牌 t），等发送完毕再切换；不支持的波特率回 ERROR（不支持），不切换。ESP32 接受 115200、230400、460800、921600、1500000、2000000、3000000。
3. 电脑收到 PONG 后切到新波特率，发 PING（最多 3 次、每次等 150 毫秒）。收到 PONG 就留在新波特率。
4. 没收到：电脑退回 921600，继续每 150 毫秒发 PING，最多 1.5 秒。ESP32 切换后 1 秒内没有收到合法帧也自己退回原来的波特率，所以两边会在 921600 重新对上。
5. 连接是芯片自带的 USB 串口（能力位 0x10）或 UDP 时，ESP32 照样回 PONG 但不改任何东西，电脑也不发 SET_BAUD。
6. ESP32 停在 921600 以外的波特率时，连续 2 秒没有收到任何合法帧（电脑断开或程序退出），自己退回 921600，下一次连接照常在 921600 握手。
7. 经 USB 转串口芯片连接、在 921600 握手时什么都没听到（第 4 节第 3 条里的"什么都没有"）时，电脑先切到 2000000 再发一次 HELLO_REQ、等同样长的时间：板子可能还停在上一次连接的 2000000（断开后不到 2 秒就重连）。收到 HELLO 就留在 2000000、不再发 SET_BAUD；没收到就退回 921600，按第 4 节第 3 条处理。

## 7. Wi-Fi 与标签

- 每个 UDP 数据报 = 一个完整的帧 + 16 字节标签；标签 = HMAC-SHA256（密钥，整帧字节）的前 16 字节。标签不对或长度不对的数据报直接丢掉，不回任何东西。
- 密钥 32 字节，由电脑在设置 Wi-Fi 时随机生成，经串口的 WIFI_SET 交给 ESP32（存在 NVS），电脑把它记在数据目录的 `esp32-boards.json`（按 MAC 记）。没有密钥的板子不收任何 UDP。
- ESP32 回复发到最近一个合法数据报的来源地址与端口。
- mDNS：服务 `_gs-esp32._udp`，端口 4545，实例名是板子的名字；TXT 记录 `id`（MAC 的 12 位小写十六进制）、`name`（名字）、`chip`（芯片型号，如 `esp32s3`）。电脑按 `id` 找密钥；手动填地址时依次试已知的密钥。

## 8. 旧固件（QineTouch v3.2）

旧固件不认 v2 的帧，也不回 HELLO。打开串口 300 毫秒内没有 HELLO 时，电脑按板子发来的字节判断：

- 文字里有 `QineTouch`（旧固件的招呼；QineTouch 的源码不在本仓库，电脑拿这个名字当标记），或整段都是 12 字节的旧触点包（`F4` 开头）→ 当作旧固件，处理见下。
- 出现 `waiting for download` → 板子停在 ROM 的串口下载模式，请按 RST。
- 出现 `ESP-ROM`、`rst:` 或 `boot:` → 板子在反复重启，带 `rst:` 后面的复位原因。
- 有字节但认不出 → 端口或波特率不对。
- 一个字节都没有 → 这个口上没有东西应答；两个 USB 口的 S3 要接标着 COM / UART 的那个口。

除第一种外都不再当作旧固件。旧固件的处理是：

- 只发触摸。每个触点一个 12 字节的包：`F4 | 按下 u8 | 编号 u8 | X u32 | Y u32 | 触点数 u8`，坐标 0～32767。
- 一帧里的每个触点（按着的与这一帧抬起的）各发一包，触点数是这一帧的触点总数。
- 不发 v2 帧（PING、按键、鼠标、手柄都不发），以免旧固件把其中的 0xF4 当成包头。
- 界面上写“旧固件，建议刷写新固件”。

## 9. 刷写

刷写走 ESP32 ROM 的串口下载协议（乐鑫公开的串口协议文档；不是本协议），由电脑端 `src/espflash` 实现。进入下载模式的方法：

1. 板子跑着本固件时，发 ENTER_DOWNLOAD；
2. USB 转串口芯片：经典的 DTR / RTS 复位时序（EN 拉低，再在 IO0 拉低时放开 EN）；
3. 芯片自带的 USB 串口：USB-Serial/JTAG 的 DTR / RTS 时序；
4. 都不行时请用户按住 BOOT 再插上数据线。

## 10. 手机那头（HID 报告）

两种接法用同一套报告：USB（S3、S2、P4）是一个组合设备里的四个 HID 接口；蓝牙（ESP32、C3、C6）是一个 HID 服务里的多个报告编号。

| 报告编号 | 内容 |
|---|---|
| 1 | 触摸屏输入：`触点数 u8` + 10 × `{按下 1 位 + 7 位填充, 编号 u8, X u16, Y u16}`，共 61 字节（加报告编号 62 字节，装得进全速 USB 的 64 字节包） |
| 2 | 触摸屏特性报告“最多触点数” = 10 |
| 3 | 键盘：`修饰键 u8, 保留 u8, 按键 6 × u8` |
| 4 | 消费类按键：`用法 u16` |
| 5 | 鼠标：`按键 u8, X i16, Y i16, 滚轮 i8` |
| 6 | 手柄：`按键 u32, 方向键 u8, X i16, Y i16, Z i16, Rz i16, 刹车 u8, 油门 u8` |

USB 的四个接口：0 触摸屏（报告 1、2）、1 键盘与消费类按键（报告 3、4）、2 鼠标（报告 5）、3 手柄（报告 6）。P4 用高速 USB，中断端点每 125 微秒轮询一次；全速 USB 每 1 毫秒一次。

## 11. 向量

`vectors.json`：`crc`（CRC 已知值）、`sha256`（SHA-256 已知值）、`messages`（每条消息的字段、负载与整帧）、`invalidPayloads`（解码必须失败的负载）、`invalidFrames`（单帧解码必须失败的字节：截断、CRC 错、帧头错、长度超限、多出字节）、`streams`（字节流同步：期望找出的帧、坏帧数、丢掉的字节数，逐字节喂与整块喂结果相同）、`tags`（UDP 标签）、`legacy`（旧固件的 12 字节包）。
